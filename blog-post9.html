Research log: what OpenVLA taught me about prompt sensitivity

Oct 2026  ·  project vlog  ·  research log

Most of my projects were built to ship. The OpenVLA project was different: it was built to answer one question properly. If the scene stays exactly the same but I change the wording of the instruction, does a robot-action model still predict the same action?

The setup

I used OpenVLA-7B with BridgeData images and tested four prompt styles on every image: a normal instruction, a paraphrase, a contradictory instruction, and a neutral one. I ran two experiment branches. The first used 40 manually curated trajectories (80 images, initial and final frames). The second used 50 automatically sampled trajectories from the scripted archive.

What I found

Paraphrases stayed closest to the normal prompt, which is the result you hope for. Contradictory and neutral prompts caused larger drift in the predicted action. In the manual set, the average drift on initial frames went from about 0.028 for paraphrases to about 0.045 for neutral prompts. Final-state images were generally more fragile than initial-state images, so the model was less stable exactly when the task was nearly finished.

In the auto-sampled set the gaps were smaller and not perfectly ordered, which is a good reminder that one clean pattern in one dataset is not a law.

What the project taught me

First, evaluation is engineering. The valuable part was not running inference once. It was automating runs, tracking experiments, writing out CSVs, computing bootstrap confidence intervals, and generating figures so that anyone could rerun the pipeline and get the same numbers.

Second, failure analysis beats a headline number. The most interesting rows were the failure cases, because they showed which scenes and wording made the model unreliable.

Third, honest reporting matters. Some comparisons were close, and I kept them in the write-up instead of hiding them.

A model that works on your prompt is a demo. A model that works when the prompt changes is a system.

The full code, results, and reports are in the OpenVLA repository.
